# Product landscape: proactive / background / scheduled / ambient AI agents (as of 2026-11-01)

Scope note: research pass of about 18 search/fetch calls. Primary docs were fetched for Claude Code scheduled tasks (formerly routines) and Devin Automations. Other items rely on vendor blogs and changelogs where search surfaced them, otherwise on secondary press and blogs (flagged). Products I could not research are listed under Gaps and should not be treated as verified.

## Anthropic: Claude Code scheduled tasks (formerly "routines"), /schedule, API and GitHub triggers, local scheduling

### Takeaway
Anthropic's main proactive surface is Claude Code **cloud scheduled tasks**, launched as "routines" around 2026-04-14 and since renamed. A task is a saved prompt plus repos plus connectors, run as a full cloud Claude Code session. Three triggers can be combined: schedule (cron, at most hourly), API (`/fire` endpoint with a bearer token) and GitHub events. Runs start in **auto mode**: a classifier approves actions and a prompt is raised only on ask-rules or repeated blocks. Each run's output is a reviewable session, with work on `claude/` branches. Cost comes out of the subscription, with hard hourly run caps. The feature is still in research preview.

### Cited Findings
- The docs now call the feature "scheduled tasks, formerly routines": a saved configuration (prompt, one or more repos, connectors) that runs on Anthropic-managed cloud, or on an org's self-hosted environment, "so they keep working when your laptop is closed". It is in **research preview**, and behavior, limits and the API may change. — [Claude Code docs: Automate work with scheduled tasks](https://code.claude.com/docs/en/routines)
- Trigger types: **Schedule** (hourly, nightly, weekly or a one-off future time), **API** (HTTP POST to the task's own endpoint with a bearer token) and **GitHub** (repo events). One task can combine triggers, for example a nightly PR review that also fires from a deploy script and on every new PR. — [Claude Code docs](https://code.claude.com/docs/en/routines)
- Supported GitHub events: Pull request (opened, closed, assigned, labeled, synchronized and more), Release (created, published, edited, deleted) and Issue (opened, edited, closed, labeled, assigned and more), with PR filter fields. Each event starts a new independent session, never a reused one. GitHub webhook events have per-task and per-account hourly caps, and events over the cap are **dropped**. — [Claude Code docs](https://code.claude.com/docs/en/routines)
- Cron minimum interval: "Expressions that run more often than once per hour are rejected." Runs scheduled exactly on the hour can start several minutes late. — [Claude Code docs](https://code.claude.com/docs/en/routines)
- API trigger: POST to `/fire` with an optional freeform `text` field such as an alert body. The fire text is wrapped and treated as **untrusted data** unless the saved prompt explicitly opts in to acting on it, because "anyone holding the bearer token can send `text`". The endpoint ships under beta header `experimental-cc-routine-2026-04-01`. The response returns a session URL to watch the run live. — [Claude Code docs](https://code.claude.com/docs/en/routines)
- Trust model: the fired saved prompt is treated as the assignment, but it "is therefore not live user input and can't act as approval or consent for actions during the run." — [Claude Code docs](https://code.claude.com/docs/en/routines)
- Gating: cloud runs begin in **auto mode**, where a classifier allows or blocks actions. A permission prompt appears in the run's session only for ask-rule matches or after repeated blocks pass a threshold, and the run then waits for a human. Artifacts are published without asking in auto mode, private by default. — [Claude Code docs](https://code.claude.com/docs/en/routines)
- Output surfacing: each run is a full session listed under History, showing Succeeded, Failed or Cancelled. The docs warn the status says how the session ended, "not whether Claude completed the work". Claude pushes to `claude/`-prefixed branches by default, and users are told to use GitHub branch protection or rulesets to restrict pushes. Actions appear as the user: commits under their GitHub identity and Slack or Linear actions under their linked accounts. — [Claude Code docs](https://code.claude.com/docs/en/routines)
- Users can ask why a run did nothing, for example `/schedule why did my nightly review do nothing this morning?`, and Claude reads the run logs and explains (requires CLI v2.1.227+). If GitHub auth expires, runs are skipped for up to 72h, then the task turns off. — [Claude Code docs](https://code.claude.com/docs/en/routines)
- Limits: runs draw subscription usage like interactive sessions do. On top of that there are hourly caps with no overage: 100 scheduled runs per hour per account (excess runs wait), 30 per hour per task for Run-now, API fires and one-off reruns combined, and 100 API fires per hour per account. Past the subscription limit, orgs with usage credits continue on metered overage, otherwise runs are rejected. — [Claude Code docs](https://code.claude.com/docs/en/routines)
- Availability: Pro, Max, Ultra, Team and Enterprise. Requires a claude.ai login (not a Console API key, Bedrock or Vertex). Admins can disable it org-wide with the "Scheduled tasks (Was Routines)" toggle. Created via claude.ai/code/routines, the Desktop app or `/schedule` (alias `/routines`), for example `/schedule daily PR review at 9am`. — [Claude Code docs](https://code.claude.com/docs/en/routines)
- Local alternatives: **Desktop scheduled tasks** and **`/loop`** run on the user's machine and stop when the machine or session stops. — [Claude Code docs](https://code.claude.com/docs/en/routines); [agentsroom.dev comparison](https://agentsroom.dev/blog/claude-code-routines-cloud-vs-local-scheduled-tasks)
- Launch date of 2026-04-14 as a research preview (secondary source). — [codex.danielvaughan.com, 2026-04-14](https://codex.danielvaughan.com/2026/04/14/claude-code-routines-launch/); [makerkit guide](https://makerkit.dev/blog/tutorials/claude-code-routines-guide)
- The same creation dialog also creates scheduled tasks for **claude.ai chat**, not only Claude Code, which suggests a shared scheduler across Claude surfaces. — [Claude Code docs](https://code.claude.com/docs/en/routines)

### Inferences
- Anthropic's design leans on "auto-act inside a sandbox, review afterwards": a classifier gates actions, work goes to branches, and every run becomes a session with a transcript. It does not use a propose-first inbox. Proactive initiative is user-authored (a saved prompt). The agent does not decide what to work on.
- Treating trigger payloads as untrusted unless opted in, and saying a scheduled prompt is not consent, are notable safety patterns worth copying in a harness.

### Gaps
- Not researched in this pass: Claude app (consumer) memory and proactive features, the Claude Agent SDK hooks reference, Claude Code GitHub Actions (`anthropics/claude-code-action`), and reception or adoption numbers for routines. No primary Anthropic launch blog was fetched.
- No user-reception data (HN or Reddit) was gathered for routines.

## OpenAI: ChatGPT Pulse, ChatGPT Tasks / Scheduled, ChatGPT agent, Codex (cloud, automations, code review)

### Takeaway
OpenAI's consumer proactivity went from **Pulse** (Sept 2025, Pro-only, an overnight personalised card feed) to **scheduled tasks** as the single hub. Multiple sources report that Pulse was **sunset on 2026-06-17**, with "proactive updates" folded into scheduled tasks, including monitoring tasks that notify only on meaningful change. On the developer side, the Codex app has local **Automations** (schedule plus prompt, with results in a review queue). DevDay 2026 (October) added **Code Review** (auto PR review on GitHub, GitLab in preview) and **Codex Security Cloud** (scheduled repo vulnerability scans, research preview).

### Cited Findings
- Pulse launched 2025-09-25 for Pro users. It researches overnight from chat history, memory and connected apps (Gmail, Google Calendar) and presents morning briefing cards. — [TechCrunch, 2025-09-25](https://techcrunch.com/2025/09/25/openai-launches-chatgpt-pulse-to-proactively-write-you-morning-briefs/)
- **Deprecated:** a 2026-06-17 ChatGPT release note reads "Pulse is being sunset as proactive updates move into scheduled tasks," and Pro users kept access for 14 days. — [Digit.in](https://www.digit.in/news/general/openai-is-retiring-chatgpt-pulse-and-replacing-it-with-scheduled-tasks-here-is-why.html); [techdevnotes release mirror, 2026-06-17](https://techdevnotes.com/releases/chatgpt-web/20260617-185205Z-45a2d2c45f03); [yellow.com (FR)](https://yellow.com/fr/news/chatgpt-pulse-scheduled-tasks-hub). Caveat: I did not fetch OpenAI's own release notes page, so these are mirrors and secondary reports.
- Replacement: a sidebar **"Scheduled"** page to view upcoming tasks and next run times, and to pause, resume, edit or delete them. Tasks can be scheduled for exact times or broader windows. **Monitoring tasks** watch the web or connected apps and "notify only on meaningful changes". — [Digit.in](https://www.digit.in/news/general/openai-is-retiring-chatgpt-pulse-and-replacing-it-with-scheduled-tasks-here-is-why.html); [yellow.com](https://yellow.com/fr/news/chatgpt-pulse-scheduled-tasks-hub)
- Scheduled tasks plan availability conflicts across sources. Reports variously say Plus, Pro, Business and Enterprise; Go included; or Free with up to 3 active tasks recurring at most daily. — [Justin McKelvey blog](https://justinmckelvey.com/blog/chatgpt-pulse); [aiweekly](https://aiweekly.co/node/3144). These are unverified secondary sources.
- Codex app **Automations**: an Automations panel where each automation has a schedule and a prompt, running on a local project or a dedicated worktree. Results go to a review queue. The Mac app launched 2026-02-02 and Windows 2026-03-04 (secondary). — [OpenAI Academy: Codex automations](https://openai.com/academy/codex-automations); [codex.danielvaughan.com, 2026-04-08](https://codex.danielvaughan.com/2026/04/08/codex-desktop-automations/); [codex.danielvaughan.com, 2026-03-27](https://codex.danielvaughan.com/2026/03/27/codex-cli-automations-scheduled-tasks/); [developertoolkit.ai](https://developertoolkit.ai/en/codex/automate/automation/)
- DevDay 2026 (around 2026-10-08) introduced Codex Code Review. It automatically reviews PRs on GitHub (GA) and GitLab MRs (preview), triggered by adding Codex as a reviewer or by commenting `@codex review`. **Codex Security Cloud** runs scheduled full-repository vulnerability scans (research preview; Pro, Business, Enterprise, Edu). Codex cloud tasks are not available on Free. — [codex.danielvaughan.com DevDay recap, 2026-10-08](https://codex.danielvaughan.com/2026/10/08/openai-devday-2026-recap-codex-cloud-agents-view-gpt61-sol-code-review-security-cloud/); [apidog blog](https://apidog.com/blog/codex-devday-2026-updates/). Both are secondary.
- Practitioner caution: treat Codex automations in CI as untrusted code execution, start with read-only tasks, and know where scheduled agents "must not" replace pipelines. — [codex.danielvaughan.com, 2026-07-18](https://codex.danielvaughan.com/2026/07/18/codex-automations-lightweight-ci-scheduled-agents-github-actions-boundary-unsupervised-risk/); [2026-07-19](https://codex.danielvaughan.com/2026/07/19/codex-automations-lightweight-ci-scheduled-agents-codex-exec-github-actions/)

### Inferences
- The Pulse sunset is the strongest market signal in this pass. A fully agent-initiated, unprompted feed was folded back into user-authored schedules plus "notify on meaningful change" monitors. A plausible reading is that agent-decided proactivity was expensive (Pro-only, overnight compute) and that user-defined triggers with change-detection gating are more sustainable. This is inference: OpenAI's stated rationale was not retrieved.
- Codex follows the same coding-agent pattern as others: schedule plus prompt, worktree isolation, and a review queue or PR as the landing surface.

### Gaps
- OpenAI's own Help Center or release notes for scheduled tasks were not fetched, so plan limits and task caps are unconfirmed. Original ChatGPT Tasks (beta, Jan 2025) details were not re-verified.
- ChatGPT agent (Operator successor) and any scheduling of agent-mode runs were not researched.
- No adoption or retention numbers for Pulse were found from reliable sources. One blog cited stats that I could not trace, so they were excluded.

## Google: Jules (Suggested and Scheduled Tasks), Gemini Scheduled Actions, CC (Labs) and Daily Brief, Project Mariner

### Takeaway
Google has the most explicit **agent-initiated** coding feature. Jules **Suggested Tasks** (Dec 2025, experimental, AI Pro and Ultra) scans repos, starting with `#TODO` comments, and proposes tasks for approval in a dashboard, with opt-in per repo. Jules **Scheduled Tasks** handle recurring upkeep. On the consumer side, **Gemini Scheduled Actions** (June 2025) allow at most 10 active actions on paid tiers. **CC** (Google Labs, Dec 2025) is an email-delivered "Your Day Ahead" briefing agent you can reply to.

### Cited Findings
- On 2025-12-10 Google announced that Jules would become "a proactive AI partner". **Suggested Tasks** scan connected repos, starting with #TODO comments, and propose work that appears in the dashboard for approval. It is enabled with a "proactive suggestions" toggle on the repo page, is experimental, and rolled out to Google AI Pro and Ultra. Coverage says it is limited to up to 5 repos. **Scheduled Tasks** (recurring jobs) and a Render integration were "available to everyone". — [Google blog: New updates make Jules a proactive AI partner](https://blog.google/technology/developers/jules-proactive-updates/); [Jules changelog 2025-12-10](https://jules.google/docs/changelog/2025-12-10); [Jules docs: Scheduled Tasks](https://jules.google/docs/scheduled-tasks/)
- The Jules Scheduled tab sits under the dashboard text field and shows status and next run times. — [Jules docs](https://jules.google/docs/scheduled-tasks/)
- Gemini app **Scheduled Actions** were announced 2025-06-06 and are limited to Google AI Pro, Ultra and qualifying Workspace plans, with **max 10 active** scheduled actions. Personal accounts need Keep Activity turned on. — [Google blog: Scheduled actions in Gemini app](https://blog.google/products-and-platforms/products/gemini/scheduled-actions-gemini-app/); [9to5Google, 2025-06-06](https://9to5google.com/2025/06/06/gemini-app-scheduled-actions/); [TechRadar](https://www.techradar.com/computing/artificial-intelligence/geminis-new-scheduled-actions-feature-puts-catching-up-with-chatgpt-on-its-dayplanner); [Android Authority](https://www.androidauthority.com/gemini-scheduled-actions-rollout-3565152)
- **CC** (Google Labs, 2025-12-16) is an experimental Gemini-based agent. It connects Gmail, Calendar and Drive and emails a daily "Your Day Ahead" briefing. It drafts emails and creates calendar links, and users **reply to the email** to steer it. It is early access for paid subscribers 18+ in the US and Canada, via waitlist, and is standalone (not in Workspace or Gemini apps). — [9to5Google, 2025-12-16](https://9to5google.com/2025/12/16/google-labs-cc/); [SiliconANGLE, 2025-12-16](https://siliconangle.com/2025/12/16/google-tests-cc-ai-agent-summarize-email-calendars-documents/)
- One unconfirmed report says a Gemini "Daily Brief" in the sidebar, requiring Personal Intelligence, may succeed CC. — [quantrimang (VN)](https://quantrimang.com/tinh-nang-daily-brief-cua-gemini-217237). I could not verify this from a Google source.

### Inferences
- Jules Suggested Tasks is the clearest "propose, then human approves" instance of agent-chosen work. It is scoped (TODO comments, 5 repos, opt-in per repo), which looks like deliberate noise control.
- CC's email-as-interface (deliver into an existing inbox, reply to steer) is a low-friction surfacing pattern distinct from in-app feeds.

### Gaps
- Project Mariner status in late 2026, Gemini on Android/Workspace proactive features (for example Magic Cue), and Jules pricing and task quotas were not researched.
- Reception of Jules suggestions (quality, noise) was not found.

## Microsoft and GitHub: Copilot Studio autonomous agents, GitHub Copilot coding agent and code review, consumer Copilot

### Takeaway
Microsoft's enterprise story is **event-triggered autonomous agents** in Copilot Studio (email arrives, document created, Dataverse row updated). They run under the configuring user's credentials, and Microsoft guidance recommends a human approval step for sensitive actions, often via Power Automate approvals. GitHub's coding agent is the canonical "assign issue → draft PR" pattern, billed in premium requests plus Actions minutes. It drew sharp public criticism in May 2025 for low-quality PRs on dotnet/runtime.

### Cited Findings
- Copilot Studio autonomous agents "take action without waiting for a user prompt", perceiving events and executing tasks "by using triggers, instructions, and guardrails you define". — [Microsoft Learn: Autonomous agents guidance](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/autonomous-agents)
- Event triggers include an email arriving, a document being created and a table row being updated (2024 wave 2 release plan). — [Power Platform release plan](https://learn.microsoft.com/en-gb/power-platform/release-plan/2024wave2/microsoft-copilot-studio/create-automated-copilots-triggered-events)
- Guidance: request human approval or confirmation before sensitive actions, verify that triggering events are authentic (email triggers can be spoofed), use least privilege, and log triggers, decisions and actions for audit. — [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/autonomous-agents)
- Triggers can run with end-user credentials (secondary summary of a message center post). — [handsontek](https://m365admin.handsontek.net/?p=13734)
- GitHub Copilot coding agent entered public preview 2025-05-19. Users assign an issue to Copilot from GitHub.com, Mobile or the CLI, and it opens a PR. It reached Business on 2025-06-24 and Pro on 2025-06-25. — [GitHub changelog 2025-05-19](https://github.blog/changelog/2025-05-19-github-copilot-coding-agent-in-public-preview/); [GitHub blog](https://github.blog/news-insights/product-news/github-copilot-meet-the-new-coding-agent/); [changelog 2025-06-24](https://github.blog/changelog/2025-06-24-github-copilot-coding-agent-is-now-available-for-copilot-business-users/); [changelog 2025-06-25](https://github.blog/changelog/2025-06-25-github-copilot-coding-agent-is-available-for-copilot-pro-users-in-public-preview)
- Cost: it consumes premium requests, charged to the person who assigned the issue, plus GitHub Actions minutes. Sources disagree on the per-task count: "one premium request per model request", "one per session × model multiplier", and a third-party estimate of 30-50 per session. Copilot opens one PR at a time and won't work on PRs it didn't create. — [morphllm guide](https://www.morphllm.com/copilot-coding-agent); [DEV Community](https://dev.to/thelogicwarlock/assign-to-copilot-explained-what-githubs-coding-agent-actually-does-59g9). These are secondary; GitHub billing docs were not fetched.
- Reception (May 2025): Copilot PRs on dotnet/runtime were widely mocked. Commenters counted failing tests in 3 of 4 linked PRs, and a quoted maintainer called the effort a "hail mary". — [r/ExperiencedDevs thread, 2025-05-21 (mirror)](https://redlib.hackliberty.org/r/ExperiencedDevs/comments/1krttqo/my_new_hobby_watching_ai_slowly_drive_microsoft/mtgm7yc); [TechBullion opinion piece](https://techbullion.com/ai-hype-vs-reality-in-software-development/) (contains unsupported speculation; discount).

### Inferences
- The dotnet/runtime episode is the best-known cautionary tale for "agent output lands as a PR that humans must review": review burden moves onto maintainers, and unlabeled agent PRs make it worse.

### Gaps
- Consumer Copilot proactive features (Copilot Vision, Actions, "Copilot Daily"), M365 Copilot event-triggered agents, current Copilot code review behavior and pricing, and 2026 updates to the coding agent (such as the "cloud agent" naming) were not researched in this pass.

## Others: Devin, Cursor, Zapier, Manus, Perplexity, LangChain ambient agents and Agent Inbox

### Takeaway
Devin and Cursor have converged on near-identical **"Automations"**: event and schedule triggers from Slack, GitHub, Linear, PagerDuty and cron, plus generic webhooks. Each run is an isolated cloud-agent session, governed by rate caps and compute budgets, not per-action approvals. LangChain's **ambient agents + Agent Inbox** (Jan 2025) is the main conceptual frame for human-in-the-loop interrupts: approve, edit, respond, ignore.

### Cited Findings
- **Devin Automations** triggers: Slack (message, reaction, user-group mention); GitHub (issue, comment, PR opened or updated, review, check run, push); GitLab; Linear; Jira; Pylon; PagerDuty (incident triggered, acknowledged, resolved, updated); Schedule (hourly, daily, weekly, RRULE or run-once); and Webhook (POST with a secret). Multiple triggers act as OR. — [Devin docs: Automations](https://docs.devin.ai/product-guides/automations)
- Devin's pipeline runs trigger, then conditions, then an optional **Preflight** step (an LLM filter or script that skips the event or emits work items, defaulting to 10 items per run with a max of 50), then an action. Actions are: Start session (with the payload appended as context), Message an existing long-running session, "Triage Devin" (a persistent channel-watching Devin that spawns child sessions) or an email notification. "Run now" bypasses Preflight. — [Devin docs](https://docs.devin.ai/product-guides/automations)
- Devin's cost and noise controls: invocation limit per window (example 10/hour), a default rate limit of 50 runs/hour (150/hour for Slack triage), queueing with concurrency and depth limits (overflow dropped), and an optional per-session **ACU cap** that stops the session. No human approval step is described before actions run. — [Devin docs](https://docs.devin.ai/product-guides/automations)
- Devin output by template: Slack thread replies (bug triage, alert RCA), fix PRs (Sentry errors daily, CI failures), a changelog PR, Slack or Notion digests and Linear tickets, plus an Activity tab and email notifications. — [Devin docs](https://docs.devin.ai/product-guides/automations)
- Devin pricing (secondary, conflicting): Core from $20 plus pay-as-you-go at $2.25/ACU; Team $500/month including 250 ACUs; an ACU is about 15 min of active work. — [fast.io pricing](https://fast.io/resources/devin-ai-pricing.md); [fast.io ACU guide](https://www.fast.io/resources/devin-acu-guide.md)
- **Cursor Automations** launched around 2026-03-05. Agents "run on schedules or are triggered by events" such as a Slack message, a new Linear issue, a merged GitHub PR or a PagerDuty incident (triggered or acknowledged). Cron triggers "may run with a delay but will not start before the indicated time". Slack triggers fire on public channels only. Automations can run **without a repo**, in which case they cannot edit code or open PRs. Example: a PagerDuty incident triggers an agent that investigates logs and proposes fixes via Slack plus a PR. Billed as cloud-agent usage. — [Cursor docs: Automations](https://cursor.com/docs/cloud-agent/automations); [Pulse2, 2026-03-09](https://pulse2.com/cursor-automations-launched-for-always-on-agentic-coding-workflows)
- **Cursor Bugbot** (auto PR review) is priced separately from Cursor subscriptions, with a Pro tier at $40/month for unlimited reviews and custom Enterprise pricing. Cursor forum users report confusion over the pricing model. Background or cloud agents bill on usage (model API pricing); third-party descriptions differ. — [Cursor pricing docs](https://cursor.com/docs/account/pricing.md); [Cursor forum](https://forum.cursor.com/t/confusion-of-bugbot-pricing/160838); [morphllm](https://www.morphllm.com/cursor-background-agents)
- **Manus via Zapier**: Zapier Schedule can create Manus tasks on daily, weekly, monthly or custom cadences. The Manus Zapier app fires instant triggers when a task is created, or when it completes, **requests input**, becomes pending or errors. A new prompt can continue an existing task. — [Zapier: Manus + Schedule](https://zapier.com/apps/manus/integrations/schedule/255669233/schedule-daily-tasks-in-manus-with-schedule-by-zapier); [Zapier: Perplexity + Schedule](https://zapier.com/de/apps/perplexity/integrations/schedule)
- **LangChain ambient agents** (Jan 2025): agents that respond to ambient signals (event streams) rather than chat prompts, asking for user input only when they find something important or need feedback. LangChain moved its UX from Slack to an **Agent Inbox** listing open human-agent interactions, where users approve, edit, respond to or ignore actions. Harrison Chase stresses that ambient does not mean fully autonomous; it relies on LangGraph (persistence, interrupts, time travel) and LangSmith. Open-source repo: langchain-ai/agent-inbox. The inbox was "single player for now". — [LangChain blog: Introducing ambient agents](https://blog.langchain.com/introducing-ambient-agents); [Sequoia "Training Data" / Inference: Ambient Agents and the New Agent Inbox](https://inferencebysequoia.substack.com/p/ambient-agents-and-the-new-agent)

### Inferences
- Coding-agent vendors (Devin, Cursor, Claude Code) gate background work through **blast-radius controls** (sandboxed VM, branch-only pushes, rate and invocation caps, compute budgets, LLM preflight filters), not per-action approvals. Human review happens at the PR or thread. LangChain's inbox model, with per-action interrupts, is used more for personal-assistant domains (email, calendar) where actions are irreversible.
- Devin's "Preflight" LLM filter and OpenAI's "notify only on meaningful changes" both address the same problem: preventing noisy triggers from producing noisy runs.

### Gaps
- Not researched (no verified sources gathered): Replit Agent background or scheduled features, Factory droids, Lindy (triggers, pricing), Zapier Agents (native), n8n AI agent nodes, Perplexity Tasks (native scheduling), Manus native scheduler, Apple Intelligence proactive suggestions (and status of a proactive Siri), Microsoft consumer Copilot proactive features, Project Mariner. These should be marked "not covered" in the report, not filled from memory.
- Few hard adoption numbers were found for any product.

## Cross-product comparison and converging patterns

### Takeaway
The products are converging on one shape. A user-authored **"automation" or "scheduled task"** object (prompt + context/repos + connectors) carries **multiple OR'd triggers**: a cron schedule (usually at most hourly), a generic authenticated **webhook/API**, and first-party **events** (GitHub, Slack, Linear, PagerDuty, email). Each firing runs as an **isolated, fresh session**, governed by **rate caps and compute budgets**. Results land in a **reviewable artifact**: a PR or branch, a thread reply, an email or digest, or a session transcript in a run-history list. Agent-*chosen* proactivity (Pulse, Jules Suggested Tasks) is rarer and has been scaled back or tightly scoped.

### Inferences
- **Convergence 1, the trigger triad:** schedule + webhook/API + native SaaS events, OR'd on one automation object (Claude, Devin, Cursor, and Copilot Studio via events).
- **Convergence 2, a fresh isolated session per firing,** with a run-history list where each run opens as a full transcript (Claude, Devin Activity, Codex review queue).
- **Convergence 3, controls at the run level, not the action level,** for coding agents: hourly caps, invocation windows, queues that drop overflow, compute or ACU budgets, branch prefixes and sandbox network allowlists. Per-action approval survives mainly as an escape hatch (Claude ask-rules) and in personal-assistant or enterprise flows (LangChain inbox, Copilot Studio guidance).
- **Convergence 4, noise suppression before the model runs:** Devin Preflight LLM filters, ChatGPT "notify only on meaningful changes", Jules restricted to TODOs and 5 repos, and trigger filters on PR fields (Claude).
- **Convergence 5, untrusted trigger payloads:** Claude wraps fire text as untrusted, and Microsoft warns that email triggers can be spoofed. Expect this to become standard.
- **Divergence:** agent-chosen proactivity (Pulse, Jules Suggestions, CC) versus user-authored schedules. The Pulse sunset suggests the market is retreating to user-authored triggers with change-detection, not open-ended "the agent decides what you need".
- **Landing surfaces:** coding uses PR/branch plus thread replies; consumer uses email or an in-app feed with notifications; enterprise uses the system of record plus an approval flow.

### Gaps
- Systematic reception data (complaints about notification noise, retention, adoption numbers) is thin. Only the dotnet/runtime Copilot episode and Bugbot pricing confusion were found. No reliable usage stats were found for Pulse, routines, Jules suggestions or Automations.
- Official pricing pages (Cursor, Devin, GitHub premium requests, OpenAI scheduled task caps) were not fetched directly. Figures above marked secondary should be verified before publication.
